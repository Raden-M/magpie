# SQLite and FTS5 for data and search

Date: 2026-07-23
Status: accepted

## Context

Single-user, read-heavy, admin-only writes. Search must cover the actual kept content, not just
titles, without running a second daemon.

## Decision

SQLite for structured data, FTS5 with BM25 for full-text search. Blobs on disk, referenced by
path or hash.

## Alternatives rejected

Meilisearch: typo-tolerant and better at scale, but a second service to run. It remains a drop-in
behind the same search endpoint if the corpus outgrows FTS5.

## Consequences

No typo tolerance or semantic search. SQLite compiles into the binary, which keeps the one-binary
story intact but means cross-compiling requires a C toolchain.
